# Portable audit passes

Use evidence to identify a practical defect, not to force every file through a preferred template. Keep file paths, observed lines and confidence with each finding. Resolve file roles from actual contents and current configuration. For a full audit account for F1-F9 below; targeted work selects the relevant passes explicitly.

## F1: Context and governance

Check bootstrap routing, whether essential instructions are specific enough to act on, unnecessary repeated text, stale current-focus claims, conflicts across governing files, applicable brand guidance, and engine/dependency coverage. Verify referenced paths. Read protected globals when necessary to assess a real conflict; propose changes without inventing policy. Preserve current user authority and raw provenance. The former 80/300-line thresholds and 89%/35% compliance figures are not universal rules. Check the actual host loading behavior before estimating recurring context cost.

## F2: Knowledge links and source integrity

Check the documented schema, dead wikilinks, orphan notes, missing entity cross-references, duplicate canonical records, misplaced notes, true empty stubs, unpropagated source facts and unauthorized raw-source changes. Parse aliases, anchors and path-qualified targets; handle duplicate basenames as ambiguity. Skip syntax examples, legitimate index stubs and intentionally archived/date-indexed items where local rules allow. Read both candidates before proposing a repoint or merge; similar filenames are not proof.

A source need only update the pages its content warrants. Karpathy's example of 10-15 touched pages is not an ingestion quota. File modification times or an automated commit author do not prove an improper edit; examine the actual change and authority. Never automatically remove a link, source, stub or duplicate. Verify inbound references before any authorized move or merge.

## F3: Instruction clarity

Review filler, weak procedural wording, unnecessary preambles, verbose connectors, article density, large sections and categorical mappings. Keep these as candidate-finding techniques. Preserve uncertainty about facts, meaningful qualifications, exceptions, user wording, code, paths, URLs, dates, tables, quoted speech and reference targets. Prefer clear plain language over automatic 'caveman' substitutions. Measure savings only after a meaning-preserving edit; do not promise performance gains from smaller text alone.

## F4: Context use

Inspect which files are actually loaded and when, oversized mixed-purpose documents, buried critical rules, preambles, co-loaded redundant content, concise decision summaries and Daily bloat. Long raw transcripts or references are not failures solely for being long. Loading order and measured task behavior matter more than folder proximity or vocabulary overlap. Retain essential instructions through handoff and compaction. Do not apply 3,000-token, 30%-position or median-size thresholds as proven model limits.

## F5: Storage and navigation

Review focused scope, descriptive filenames, useful indices, date naming, recoverable version history and restore evidence. Distinguish synchronization from backup and a Git directory from committed, restorable versions. Managed memory limits do not apply to arbitrary Markdown files. Do not initialize repositories, install sync software, rename notes or split files merely to pass this check.

## F6: Skill discovery and portability

Check entrypoint frontmatter against the target host's current schema; discriminating descriptions; concise relevant body; accessible supporting references; conditional loading; paths that resolve on that surface; dated/versioned capability claims; justified configurable constants; consistent terminology; connector schema discovery; private source versus packaged duplication; and clarity of invocation wording. Do not impose Claude-only metadata limits on all hosts or reject every two-hop reference. A skill is not inherently a binary .skill file.

Compare source, vault, standalone library, marketplace checkout, installed cache and account-library copies separately. Record hashes and unique changes. Cache presence is not proof of discovery or invocation. Preserve useful local operational variants privately before distribution. Host adapters own concrete tool names, settings, account scope, scheduling and output presentation. Permissions remain a host boundary; prose saying 'read-only' is not a sandbox.

## G7: Document hygiene

Apply the current workspace's actual frontmatter, title and writing conventions. Preserve raw quotations and original open tasks. A title matching a filename can be necessary for portable rendering. Use only schema-supported status values and evidence-backed completion. Resolve conflicting no-dash scopes against current user instructions before editing. Don't run broad mechanical replacements from character matches.

## F8: Cross-file reflection

Check contradictions, genuine merge candidates, superseded state, recurring themes without a useful home, and durable decisions buried in recent sessions. Distinguish changed decisions from incompatible current claims and different audiences. Use a stated session window; mtime is a retrieval hint, not decision authority. Read full relevant passages and identify the superseding source before rewriting. Don't promote assistant assertions into governance or identity rules. Preserve original sources; link conclusions back to evidence. A merge must preserve unique information and verify inbound links and recoverability.

## F9: Architecture and discoverability

Check missing required roles, truthful routing, useful/fresh engine indices, actual retrieval paths, misplaced material, duplicate responsibilities and clusters of problems that justify reorganization. Walk a realistic retrieval task from the documented entrypoint. Three hops is a design heuristic, not an absolute requirement. Include configured engines, Hunter and Life without assigning invented activation or funding rules. Propose the smallest change that resolves an observed navigation problem. Unknown folders are not automatically misfiled.

## Apply and verify

Prepare a finding list with before/after content, backups, original hashes, authorized target paths and acceptance criteria. Do not overwrite a changed source or existing unexpected output. Apply small reversible changes in dependency order. Verify readback, semantic preservation, discovery links and any affected parser or runtime. Preserve current open tasks verbatim unless their specific change is justified. On failure, stop dependent work, record which files changed and retain recovery evidence. Never blindly retry an uncertain mutation.

Use dispositions: retained, adapted, proposed, applied-and-verified, unavailable, not-applicable, declined or failed. Record counts by disposition and coverage. No aggregate 'system rot' score, guaranteed speed-up or savings projection without a valid measured basis.
